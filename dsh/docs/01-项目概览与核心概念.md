# 01 · 项目概览与核心概念

## 1. DeepSeek Harness 是什么

**DeepSeek Harness（`dsh`）** 是 DeepSeek AI 开源的 agent harness（智能体框架）：

- **产品面**：一个可直接运行的 Coding Agent。既有 Web UI，也有 headless 一次性任务、SDK、ACP 等模式。
- **框架面**：一套「一切皆插件」的架构，由 Cordis 驱动。模型适配器、工具注册表、会话日志、沙箱、UI、**Agent Loop 本身**都是插件，因此都能从配置替换。

它处于 **developer preview**，迭代很快，会有破坏兼容性的变更。

## 2. Cordis 五个核心概念

官方 [`cordis-primer.zh.md`](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/cordis-primer.zh.md) 把一切压缩成五点：

| 概念 | 含义 |
| --- | --- |
| **插件（Plugin）** | 实现 Service 的对象：带可选 `inject` 和 `apply(ctx)` 的函数，或一个 `Service` 子类 |
| **上下文（Context）** | 服务的容器。一个服务占据稳定的 `ctx.<key>`（`ctx.tools`、`ctx.llm`、`ctx.sessions`…）；其他插件按 key 查找服务，而不是 import 具体实现 |
| **依赖注入（inject）** | 插件声明所需服务，框架等它们就绪后才执行 `apply`；加载顺序由服务依赖表达，而非手动编排 |
| **类型化事件** | 服务用 TypeScript 声明合并注册事件名，然后以 `emit` / `waterfall` / `serial` / `bail` / `parallel` 分发 |
| **可逆副作用** | 提示词片段、工具 schema、适配器、监听器都通过 `ctx.effect()` / `ctx.on()` / `ctx.tools.register()` 安装，reload/teardown 时自动撤销 |

> 一句话：**没有需要打补丁的内核。** 要扩展 dsh，就把插件挂到其他插件旁边。

### 事件分发模式

| 模式 | await? | 顺序 | 返回值 |
| --- | --- | --- | --- |
| `emit` | 否 | 注册顺序观察 | 无 |
| `waterfall` | 否 | 环绕中间件，**必须调用 `next()`** | 有 |
| `parallel` | 是 | 并行观察 | 无 |
| `serial` | 是 | 按序执行，首个非空值终止 | 有 |
| `bail` | 否 | 按序执行，首个非空值终止 | 有 |

`waterfall` 不调用 `next()` 会**短路**整条流水线——这正是拦截/网关逻辑的实现方式。

## 3. Profile 与组合包（Bundle）

运行中的 `dsh` 是一棵插件树，由启动时**按层叠加**而成。

### Profile（配置档案）

- 存放在 Harness home（默认 `~/.dsh`，可用 `DSH_HOME` 覆盖）的 `profiles/<name>` 下。
- 是一个具名组装：列出它叠放的组合包、存放自己安装的树外插件、保存用户自己的 `cordis.patch.yml`。
- 随发行版交付的模板：`web`、`headless`、`sdk`、`sdk-minimal`、`acp`。

### Bundle（组合包）

- Bundle 是「**配置项 + 挂载代码**」的分发格式，因此它插入的内容始终能被上层 patch。
- Bundle 在 `package.json` 的 `dsh` 字段声明 `dsh.bundle`，指向一个 patch 文件。
- 你编写并分发 bundle；用户用 `dsh --profile <name>` 启动 profile。

两者都在各自 `package.json` 的 `dsh` 字段声明：`dsh.profile` 列出一个 profile 的组合包，`dsh.bundle` 指向一个组合包的 patch。

### 层的叠加顺序

生效配置在空条目列表之上，按以下顺序逐层组合：

1. profile 的 `dsh.profile.bundles` 列表里的各个组合包 patch（按列表顺序，先是 `@deepseek-ai/dsh-base`，再是每个已安装组合包）
2. profile 自己的 `cordis.patch.yml`
3. home 级 `$DSH_HOME/cordis.patch.yml`
4. 每个 `--patch <path>` overlay（按 argv 顺序）

**后应用的层按行胜出**，且 patch 会替换目标行的**整个 `config`**（不是深度合并）。这意味着覆盖别人的行时必须重述该行需要的每一个键。

## 4. 核心服务一览

| 服务键 | 承担 | 对应包 |
| --- | --- | --- |
| `ctx.sessions` | 仅追加的 `SessionEvent` 日志与内存存储 | `core/session` |
| `ctx.systemPrompt` | 提示词片段与工具 schema 的组装 | `core/system-prompt` |
| `ctx.tools` | 作用域化工具注册表 + 带把关的执行流水线 | `core/tools` |
| `ctx.agents` | `Agent` 接口、活跃 agent 注册表、`agent/*` 事件 | `core/agent` |
| `ctx.agentLoop` | 默认的 Agent 驱动器 | `core/agent-loop` |
| `ctx.llm` | 消息/流式词汇表与适配器 seam | `llm/llm` |
| `ctx.skills` | 技能提供方注册表 | `skill/skill` |
| `ctx.commands` | 用户斜杠命令注册表 | `interaction/commands` |
| `ctx.webhookRuntime` | 认证 delivery 分派与 Workspace Session 创建 | `webhook/webhook` |

> 完整清单以生成的[子系统页面](https://github.com/deepseek-ai/deepseek-harness/tree/main/docs/subsystems)和服务的 TypeScript 接口为准，不要维护另一份静态列表。

## 5. 三种事件域

选对事件域是大多数改动的第一个决定：

- **会话事件（Session events）**：追加到日志并通过 `session/event` 广播的**持久事实**。需要跨 reload 存在时用它。例如 `turn/end`、`tool/call`、`tool/result`、`compaction/*`。
- **Agent 事件（`agent/*`）**：携带活跃 `Agent`——inbox、步骤、状态、请求、验证、续跑。要观察/拦截进行中的工作时用它，例如 `agent/pre-step`、`agent/request`、`agent/turn-stopping`。
- **能力事件（Capability events）**：无需 import 循环即可向某个 seam 附加策略和适配器，例如 `fs/*`、`tools/pre-execute`、`tools/result`、`telemetry/*`。

> 注意：`turn/*`、`step/*`、`tool/call`、`tool/result`、`compaction/*` 是**持久化会话事件类型**，不是同名 Cordis 事件。要观察它们，监听 `session/event` 并检查 `event.type`。

## 6. 仓库布局（源码 checkout）

```
deepseek-harness/
├── apps/
│   ├── cli/          # dsh 启动器、profile、CLI 行为参考
│   ├── web/          # 浏览器应用
│   ├── desktop/      # Electron 桌面应用
│   └── desktop-host/
├── packages/
│   ├── bundle/       # base / web-app / headless / sdk-app / acp-app …
│   ├── core/         # session / system-prompt / tools / agent / agent-loop / scope
│   ├── llm/          # llm、llm-deepseek、llm-pi-ai …
│   ├── host/         # plugin-inventory、webserver …
│   ├── client/       # Web 客户端插件（ui-*）
│   ├── boot/         # app-boot、plugin-manager、cmdline、hmr
│   └── …             # skill、mcp、sandbox、subagent、plan、todo、schedule…
├── docs/             # 本教程大量引用的官方文档
├── website/          # 文档站
├── vendor/           # 以 vendor 方式引入的 cordis
└── scripts/          # 构建、门禁、生成脚本
```
