# 09 · 社区插件安装与使用

> ⚠️ **安装插件 = 在你的机器上运行第三方代码**，权限和你本人一样大：能读你的文件、用你的凭据、访问网络，**工具审批管不到插件自己的代码**。
> 收录/推荐**不等于安全审查**。装之前先看源码，不熟的插件尽量放在没有密钥、没有重要资料的环境里试。

## 1. 到哪里找插件

| 渠道 | 地址 | 说明 |
| --- | --- | --- |
| GitHub 话题 | <https://github.com/topics/dsh-plugin> | 插件作者给仓库加 `dsh-plugin` 话题即可被发现 |
| 精选列表 | <https://github.com/awesome-dsh-plugin/awesome-dsh-plugin> | 社区维护，只收录能 `dsh plugin add` 安装、声明 `dsh.bundle` 的插件 |
| 插件市场 | `dsh-market` | 装在 dsh 里的插件市场，一键安装/升级/换主题 |
| 对话式查找 | `dsh-find-plugin` | 想要什么插件直接问 agent |
| 聚合生态 | `zhu1090093659/dsh-web` | Web 插件聚合生态 |

**安装插件市场的命令**（来自精选列表）：

```sh
dsh plugin --profile web add dshmarket
# 或者
dsh plugin --profile web add dsh-find-plugin
```

装好后在 **设置 → 插件** 里用图形界面搜索、安装、升级。

## 2. 安装、更新、移除

社区插件本质就是 bundle，安装方式与第 08 课一致：

```sh
# 从 npm 安装
dsh plugin --profile web add <package-name>

# 从 GitHub 安装（注意：可能需要 allowBuilds，见下）
dsh plugin --profile web add github:owner/repo

# 安装本地 checkout / tarball
dsh plugin --profile web add ./my-plugin
dsh plugin --profile web add ./my-plugin-0.1.0.tgz

# 移除
dsh plugin --profile web remove <package-name>

# 其他 pnpm 子命令（update / why / …）照常可用
dsh plugin --profile web update
```

> `dsh plugin --profile <name> <args...>` 只是把参数转发给 profile 目录里的 pnpm。

**安装后要重启该 profile**（组合包成员变化属于启动边界）。profile 或 home 里普通 `cordis.patch.yml` 的编辑才走热重载。

**从 git 安装时**，pnpm ≥10 默认拒绝运行依赖的 `prepare` 脚本，第一次会失败；把 pnpm 打印的包键复制进 profile 的 `pnpm-workspace.yaml`：

```yaml
allowBuilds:
  <package-name>: true
```

然后重新执行 `add`。**这等于允许该包代码在安装时执行**，且不在 agent 沙箱内——只对源码可信的包授权，并锁定 commit。

## 3. 两种管理界面

### Web 插件页

侧边栏的**插件**页可以查看/启停 profile 的插件条目、选择组合包、安装/删除外部组合包。设置页的插件列表是只读清单。

### `plugin_manager` 工具（让 agent 自己管理）

Web 的 base profile 随附一个面向模型的 `plugin_manager` 工具，动作包括：

| action | 作用 |
| --- | --- |
| `list_plugins` / `list_bundles` | 列出插件条目 / 组合包（先 list 拿到准确标识） |
| `set_plugin` / `set_bundle` | 启用或禁用某个插件条目 / 组合包 |
| `install_bundle` / `remove_bundle` | 安装 / 删除组合包 |
| `list_version_exemptions` / `set_version_exemption` | 查看 / 设置版本豁免 |

要点：

- **每个动作都要求 `danger-full-access` 或本次调用的批准**；批准不改变会话权限模式。
- 改动**影响该 profile 的全部会话**。
- 安装可能执行被允许的构建脚本。
- **live profile 立即应用；startup profile 需要重启。**
- 不兼容的 DSH peer 依赖会阻止安装与激活。
- 版本豁免有崩溃/数据丢失风险：必须**明确警告用户并对确切的插件与运行时版本取得显式同意**。

在 `cordis.yml` 里手动启用该工具：

```yaml
- id: tool-plugin-manager
  disabled: false
```

## 5. 挑插件的实操流程

1. **看仓库**：是否有 `dsh.bundle` manifest？是否用 `dsh plugin add` 可装？最后更新时间？
2. **读源码**：重点看它注册了哪些工具、`tools/pre-execute` 策略、`pi.exec`/子进程调用、网络请求、文件写入。
3. **先隔离试**：在没有密钥、没有重要资料的目录/环境里装。
4. **固定版本/commit**：`dsh plugin --profile web add pkg@1.2.3` 或 `github:owner/repo#<sha>`。
5. **看兼容性**：不兼容的 DSH peer 会阻止安装；需要豁免时按第 08 课的要求显式确认风险。
6. **授权要谨慎**：`allowBuilds` 等于允许安装时代码以你的权限执行。
7. **出问题就移除**：`dsh plugin --profile web remove <pkg>`，然后重启 profile。

## 6. 官方随附的可选组合包

除了社区插件，官方也以 bundle 形式提供可选能力，安装方式完全相同。例如两个独立的 subagent 提供方：

```sh
dsh plugin --profile <name> add @deepseek-ai/dsh-subagent-codex
dsh plugin --profile <name> add @deepseek-ai/dsh-subagent-claude-code
dsh plugin --profile <name> add @deepseek-ai/dsh-subagent-codex @deepseek-ai/dsh-subagent-claude-code
dsh plugin --profile <name> remove @deepseek-ai/dsh-subagent-codex
```

> 安装后，每个已安装组合包只注册**休眠**的 Host 提供方；还需在复制出的 **Preset** 中单独启用对应工具行，新 Agent 才能看到该工具。**添加/移除组合包后重启 profile。**

## 7. 排错

| 现象 | 原因 / 解法 |
| --- | --- |
| `add` 成功但插件没生效 | 组合包成员变化需**重启 profile**；或该包没有 `dsh.bundle`，只当普通依赖 |
| git 安装失败，提示 `allowBuilds` | 按提示把包键写进 profile 的 `pnpm-workspace.yaml` 后重试 |
| 安装被拒（`incompatible-version`） | DSH peer 不兼容；升级插件或按第 08 课走显式版本豁免 |
| 想确认层是否生效 | `dsh --profile <p> --dump-config` 看有没有对应注释层 |
| 找不到插件 | 在 `topic:dsh-plugin` 或精选列表里搜，或用 `dsh-find-plugin` 问 agent |
| 插件市场里的问题 | 提到对应插件仓库或 `dsh-market` 仓库，而不是 dsh 本体 |
