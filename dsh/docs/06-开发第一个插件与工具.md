# 06 · 开发第一个插件与工具

> 这一课对应官方[第一个插件](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/user/develop/basic/index.zh.md)与[开发一个工具](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/user/develop/basic/tool.zh.md)。
> 前置：完成[从源码运行](02-安装与运行.md)（`pnpm install && pnpm run build`）。本仓库 `dsh/examples/scratch-plugin/` 已经放好这一课的完整代码。

## 1. 插件是什么（回顾）

一个插件就是导出 `apply` 函数的 TypeScript 模块，框架加载时调用 `apply(ctx)`：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'

export function apply(ctx: Context) {
  // 在这里注册能力
}
```

## 2. 创建并加载一个本地插件

在 deepseek-harness 仓库根目录创建 `scratch-plugin/`：

```
scratch-plugin/
├── cordis.yml
└── src/
    ├── my-plugin.ts
    └── greet-tool.ts
```

`src/my-plugin.ts`：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context) {
  console.log('[hello-plugin] plugin loaded!')
}
```

用 **patch overlay** 把它插进运行中的 dsh。`scratch-plugin/cordis.yml`（把路径换成你的仓库绝对路径）：

```yaml
- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'
```

启动：

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

打开 `http://127.0.0.1:3080`，启动期间终端会打印 `[hello-plugin] plugin loaded!`。

> **插件路径必须是绝对路径。** patch 文件只贡献配置，不改变 loader 解析模块路径时用的 profile 目录。

## 3. 自动清理与 `ctx.effect`

通过 `ctx` 注册的东西——事件监听、工具、定时器——在插件卸载时自动清理，无需手动 `removeListener` / `clearInterval`。

需要手动清理的资源（如网络连接）用 `ctx.effect()`：

```ts
export function apply(ctx: Context) {
  ctx.effect(() => {
    const timer = setInterval(() => console.log('heartbeat'), 5000)
    return () => clearInterval(timer)   // 插件卸载时运行
  })
}
```

## 4. 开发一个工具

把 `greet-tool.ts` 加进 patch，让模型能调用 `greet`：

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'
export const inject = ['tools']          // 等工具注册表就绪

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',          // 给模型看的
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      return `Hello, ${args.name}!`
    },
  }))
}
```

patch：

```yaml
- insert:
    - id: greet
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/greet-tool.ts'
```

重启后，在 Web UI 里输入：`Use the greet tool to greet Ada.` 模型会调用 `greet` 并收到 `Hello, Ada!`。

### `defineTool` 的约定（重要）

- **`inject` 用 `['tools']`**：Cordis 等工具注册表就绪后才加载你的插件。
- **参数已为你校验**：`defineTool` 根据 `parameters` 推导并校验 `args`；显式对象节点必须声明 `additionalProperties: true | false`，隐式参数根对象保持开放。DSL 表达不了的约束（非空字符串、正数、跨字段规则）仍需手查。
- **返回规范值**：`execute` 只返回 `output.schema` 声明的**规范化 JSON 值**，不要返回内容块。注册表校验/冻结后，再交给 `output.render(args, value)` 转成面向模型的内容。
- **抛异常 = `isError`**：基础设施故障请 `throw`；成功的领域结果即使表示不理想状态，也写入规范值由 renderer 解释。
- **遵守 `exec.signal`**：`execute(args, exec)` 的第二个参数带 `exec.signal`，取消时要停掉进行中的工作。
- **注册借用你的只读定义**：注册后不要改 schema 或替换回调；要热替换就 dispose 所属副作用再注册替代品。
- **注册是可逆副作用**：dispose 插件 fiber 即注销该工具；schema 会自动流入系统提示词的组装。

> 完整的工具编写参考（嵌套 schema、规范值、后台工作、策略钩子、PTC mode、UI 卡片）见官方 [`docs/cookbook/adding-a-tool.zh.md`](https://github.com/deepseek-ai/deepseek-harness/blob/main/docs/cookbook/adding-a-tool.zh.md)。

## 5. 让插件接受配置

导出 `Config` 类型 + 同名 Schemastery schema，默认值写在 schema 里：

```ts
import Schema from '@deepseek-ai/schemastery'

export interface Config {
  greeting: string
  maxRetries: number
  verbose?: boolean
}

export const Config: Schema<Config> = Schema.object({
  greeting: Schema.string().default('Hello'),
  maxRetries: Schema.number().default(3),
  verbose: Schema.boolean().default(false),
})

export function apply(ctx: Context, config: Config) {
  console.log(config.greeting)   // 用户值或 schema 默认值
}
```

patch 里传配置：

```yaml
- insert:
    - id: greet
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/greet-tool.ts'
      config:
        greeting: 'Hi there'
        maxRetries: 5
```

- Cordis 会用导出的 schema 校验配置并填充默认值。
- **不要导出普通对象当 `Config`**，它不满足 Cordis 要求的 Standard Schema 接口。
- 配置非法时**插件加载失败并给出明确错误**。
- **设计原则：凡是不同部署可能取不同值的参数，都必须是配置字段。** 检验标准：能否在 `cordis.yml` 里改这个值而不改代码？
- 配置变更会触发**插件热替换**：卸载旧实例、加载新实例；因为注册都属于 effect，旧注册不会残留。

## 6. HMR：改完即生效

配置了 `dsh-hmr` 时（base profile 默认启用）：

1. 卸载旧插件（清理所有注册）
2. 重新加载新代码
3. 执行新的 `apply`

改插件源码或 `cordis.yml` 配置后无需重启。若未启用 HMR，则只应用一次，需重启。
