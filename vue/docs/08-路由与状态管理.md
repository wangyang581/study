# 第一部分：Vue Router

## 1. 路由解决了什么？

SPA 只有一个 HTML，如果不做处理，地址栏永远是 `/`，刷新会丢失状态，也无法分享链接。
路由把「URL ↔ 组件」建立映射，让单页应用拥有多页面的体验：

- 可前进/后退、可收藏、可分享
- 刷新页面能恢复到同一视图
- 可以按路由做懒加载、权限控制

## 2. 基本使用

```js
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),          // HTML5 模式：/users/1（无 #）
  // history: createWebHashHistory(),   // hash 模式：/#/users/1（无需服务端配置）
  routes: [
    { path: '/', redirect: '/home' },
    { path: '/home', name: 'home', component: () => import('@/views/Home.vue') },
    { path: '/user/:id', name: 'user', component: () => import('@/views/User.vue') },
    { path: '/:pathMatch(.*)*', name: '404', component: () => import('@/views/NotFound.vue') },
  ],
  scrollBehavior: () => ({ top: 0 }),   // 切换后回到顶部
})

export default router
```

```js
// main.js
app.use(router)
```

```vue
<!-- App.vue -->
<RouterView />
```

### history 模式的服务端配置

用 `createWebHistory` 时，直接访问 `/user/1` 服务器会 404（因为没有这个文件）。
需要让服务器**把所有未匹配的请求都返回 `index.html`**：

```nginx
location / { try_files $uri $uri/ /index.html; }
```

## 3. 导航：声明式与编程式

```vue
<!-- 声明式 -->
<RouterLink to="/home">首页</RouterLink>
<RouterLink :to="{ name: 'user', params: { id: 1 } }">用户 1</RouterLink>
<RouterLink :to="{ path: '/list', query: { page: 2, sort: 'stars' } }">列表</RouterLink>
<RouterLink :to="{ path: '/x', replace: true }">不留历史</RouterLink>
```

```js
// 编程式
const router = useRouter()
router.push('/home')                                  // 压入历史栈
router.push({ name: 'user', params: { id: 1 } })
router.push({ path: '/list', query: { page: '2' } })
router.replace('/login')                              // 替换当前记录
router.back()
router.go(-1)
```

**`push` vs `replace`**：
登录成功后跳首页应该用 `replace`（避免用户点返回又回到登录页）。
表单提交后跳转通常也用 `replace`。

## 4. 读取路由信息

```js
const route = useRoute()

route.path        // '/user/1'
route.fullPath    // '/user/1?tab=info'
route.name        // 'user'
route.params      // { id: '1' }        ← 动态段，注意是字符串
route.query       // { tab: 'info' }    ← 查询参数，都是字符串
route.hash        // '#section'
route.matched     // 匹配到的路由记录数组
route.meta        // 路由元信息
```

**`params` vs `query`**：

| | params | query |
| --- | --- | --- |
| 形式 | `/user/1` | `/list?page=2` |
| 是否在路由表里声明 | 是（`:id`） | 否 |
| 适合 | 资源标识（id） | 筛选、排序、分页、搜索词 |
| 刷新后 | 保留 | 保留 |

筛选/分页状态**推荐放 query**：可分享、可刷新、可后退。

## 5. 动态路由与「组件复用」

```js
{ path: '/user/:id', component: User }
{ path: '/user/:id(\\d+)', component: User }   // 加正则约束，只匹配数字
{ path: '/:a/:b+', component: X }              // 重复参数（数组）
{ path: '/files/:path(.*)*', component: X }    // 匹配剩余路径
```

```js
// 组件复用时的数据获取：用 watch 而不是 onMounted
watch(() => route.params.id, (id) => load(id), { immediate: true })
```

## 7. 路由守卫

```js
// 全局前置守卫：权限、标题
router.beforeEach((to, from) => {
  document.title = to.meta.title ? `${to.meta.title} - 我的应用` : '我的应用'

  const token = localStorage.getItem('token')
  if (to.meta.requiresAuth && !token) {
    return { name: 'login', query: { redirect: to.fullPath } }   // 返回路由对象 = 重定向
  }
  return true        // 放行
  // return false    // 取消导航
})

// 全局后置钩子：关闭 loading、埋点
router.afterEach((to) => { trackPageView(to) })

// 解析错误
router.onError((err) => console.error(err))
```

### 组件内守卫

```js
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

onBeforeRouteLeave((to, from) => {
  if (hasUnsaved.value) {
    return window.confirm('有未保存的修改，确定离开吗？')
  }
})
onBeforeRouteUpdate((to) => load(to.params.id))
```

### 守卫的执行顺序

```
导航被触发
 → 失活组件的 beforeRouteLeave
 → 全局 beforeEach
 → 复用组件的 beforeRouteUpdate
 → 路由独享 beforeEnter
 → 解析异步路由组件
 → 被激活组件 beforeRouteEnter
 → 全局 beforeResolve
 → 导航确认
 → 全局 afterEach
 → DOM 更新
 → beforeRouteEnter 的 next 回调
```

### 常用 `meta` 组合

```js
{ path: '/admin', meta: { requiresAuth: true, roles: ['admin'], title: '后台' } }
{ path: '/public', meta: { layout: 'blank', keepAlive: true } }
```

## 8. 懒加载与打包

```js
component: () => import('@/views/Heavy.vue')          // 按路由分包
component: () => import(/* webpackChunkName: "admin" */ './Admin.vue')  // 命名分组（webpack）
```

好处：首屏只下载必要代码，大型应用首屏体积可减少 50%+。
本项目就是这么做的（见 `src/router/index.js` 与 `src/course.js`）。

## 9. 路由常见坑

| 坑 | 说明 |
| --- | --- |
| 用 history 模式但没配服务端 | 刷新 404 |
| `params` 传对象/数字 | 会被转成字符串，取出来要手动 `Number()` |
| 组件复用时不重新请求 | 用 `watch(() => route.params.x, ..., { immediate: true })` |
| 直接改 `route.query` | 要 `router.push({ query: {...} })` |
| 守卫里 `return` 写成 `next()` 混用 | 二选一，别混用（Vue Router 4 推荐返回值写法） |

# 第二部分：Pinia 状态管理

## 1. 什么时候需要 store？

**判断标准**：如果这份数据「提升到共同父组件后，需要层层透传 props」，就该用 store。

适合放 store：

- 登录用户信息、权限
- 购物车、全局通知/消息
- 主题、语言等全局配置
- 多个页面共享的筛选条件

**不适合**放 store：

- 只在一个组件/页面里用的状态（放组件里）
- 表单的临时输入（放组件里）
- 可以从其他状态推导出来的（用 `computed`）
- 能通过 URL 表达的（放 `route.query`）

## 2. 定义 store

**组合式写法（推荐）**：

```js
// stores/counter.js
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  // state
  const count = ref(0)

  // getters
  const double = computed(() => count.value * 2)

  // actions
  function increase(step = 1) { count.value += step }
  async function fetchCount() { count.value = await api.getCount() }

  return { count, double, increase, fetchCount }
})
```

**选项式写法**：

```js
export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  getters: {
    double: (state) => state.count * 2,
    doublePlusOne() { return this.double + 1 },   // 用 this 访问其他 getter
  },
  actions: {
    increase() { this.count++ },
    async fetchCount() { this.count = await api.getCount() },  // 支持 async
  },
})
```

## 3. 在组件中使用

```js
import { storeToRefs } from 'pinia'
import { useCounterStore } from '@/stores/counter'

const store = useCounterStore()

// ✅ 状态/getter 解构必须用 storeToRefs，否则丢响应式
const { count, double } = storeToRefs(store)

// ✅ action 是普通函数，直接解构
const { increase } = store

// 也可以直接用
store.count++
store.increase(5)
```

> ⚠️ **这是 Pinia 最常见的坑**：`const { count } = store` 会让 `count` 变成普通数字。

## 4. 修改 state 的方式

```js
store.count++                       // ① 直接改（Pinia 允许）
store.$patch({ count: 10 })         // ② 批量修改（性能更好，只触发一次）
store.$patch((state) => { state.count++; state.list.push(x) })  // ③ 函数式
store.increase()                    // ④ 通过 action（推荐，逻辑集中）
store.$reset()                      // ⑤ 重置为初始 state
```

**最佳实践**：**复杂修改一律写进 action**，组件只负责调用。
这样「谁改了数据、怎么改的」一目了然，也方便加日志/埋点/回滚。

## 5. 在 store 里使用其他 store

```js
export const useCartStore = defineStore('cart', () => {
  const user = useUserStore()          // 直接调用另一个 store
  const items = ref([])
  const summary = computed(() => `${user.name} 有 ${items.value.length} 件商品`)
  return { items, summary }
})
```

## 6. 持久化

Pinia 本身不做持久化。两种方式：

```js
// ① 手动：在 store 里 watch 写入 localStorage
watch(cart, (v) => localStorage.setItem('cart', JSON.stringify(v)), { deep: true })

// ② 插件：pinia-plugin-persistedstate
defineStore('cart', () => { ... }, { persist: { key: 'cart', storage: localStorage } })
```
