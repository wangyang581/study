## 1. `ref` 与 `reactive`

```js
import { ref, reactive } from 'vue'

const n = ref(0)                          // 任意类型
n.value++                                 // 脚本里必须 .value

const user = reactive({ name: 'a', age: 1 })  // 只能包对象/数组/Map/Set
user.age++                                // 直接改属性
```

| | `ref` | `reactive` |
| --- | --- | --- |
| 能包的类型 | 任意（数字、字符串、对象…） | 仅对象类型 |
| 脚本里访问 | `.value` | 直接属性 |
| 模板里 | 顶层自动解包 | 直接属性 |
| 重新赋值 | `n.value = {}` ✅ | 不能整体替换（会失去响应式） |
| 解构 | 天然支持 | **解构会丢响应式** |

**选择建议**：

- 基础类型 → `ref`
- 一组相关的表单字段 → `reactive` 或 `ref({...})`
- **不确定就用 `ref`**（`ref` 包对象时，内部也会用 reactive 做深层代理）

### `reactive` 的解构陷阱

```js
const state = reactive({ a: 1, b: 2 })

// ❌ plainA 只是「1」的副本，永远不会变
const plainA = state.a

// ✅ 用 toRefs 转成 ref，保持与源对象的双向连接
const { a, b } = toRefs(state)
a.value = 5      // 等价于 state.a = 5
state.a = 9      // a.value 也变成 9
```

> 同名工具 `toRef(obj, 'key')` 用于单个属性，常用于把 props 的某个字段转成 ref。

### props 解构也是同理

```js
const props = defineProps({ title: String })
const { title } = props        // ❌ 丢响应式

import { toRef } from 'vue'
const title = toRef(props, 'title')   // ✅

// 或者直接不解构，始终写 props.title —— 最省心
```

## 2. `computed`：派生数据

```js
const firstName = ref('张')
const lastName = ref('三')

const fullName = computed(() => firstName.value + lastName.value)
```

**两个特性**：

1. **自动追踪依赖**：函数体里读到了哪些响应式数据，就依赖它们。依赖变了，值自动重算。
2. **缓存**：依赖没变时，多次读取直接返回缓存值，不会重复执行函数。

### 可写 computed

```js
const fullName = computed({
  get: () => `${firstName.value}${lastName.value}`,
  set(val) {
    firstName.value = val[0] ?? ''
    lastName.value = val.slice(1)
  },
})
fullName.value = '李四'   // 会走 setter
```

### computed vs 方法

```vue
<p>{{ total }}</p>        <!-- computed：依赖不变 → 用缓存 -->
<p>{{ getTotal() }}</p>   <!-- 方法：每次重新渲染都会重新执行 -->
```

只要值能「算出来」，就用 `computed`。它让模板更短、逻辑更集中、还性能更好。

### 实战：链式派生（购物车）

```js
const totalPrice = computed(() => cart.value.reduce((s, i) => s + i.price * i.count, 0))
const discount   = computed(() => (totalPrice.value >= 500 ? 0.9 : 1))
const payable    = computed(() => (totalPrice.value * discount.value).toFixed(2))
```

层层推导，清晰好维护。

## 3. `watch`：处理副作用

「有了新值之后要去做某件事」（发请求、写 localStorage、打点、操作 DOM）→ 用 `watch`。

```js
// ① 侦听单个 ref
watch(keyword, (newVal, oldVal) => {
  console.log(`从 "${oldVal}" 变成 "${newVal}"`)
})

// ② 侦听多个源
watch([firstName, lastName], ([nf, nl], [of, ol]) => { ... })

// ③ 侦听 reactive 对象的属性（写成 getter）
watch(() => user.age, (n, o) => { ... })

// ④ 深度侦听（对象内部任意变化）
watch(obj, cb, { deep: true })

// ⑤ 立即执行一次
watch(keyword, cb, { immediate: true })

// ⑥ 停止侦听
const stop = watch(keyword, cb)
stop()
```

### `watch` vs `watchEffect`

| | `watch` | `watchEffect` |
| --- | --- | --- |
| 依赖 | 显式指定 | 自动收集函数体里读到的响应式数据 |
| 新旧值 | 能拿到 | 拿不到 |
| 执行时机 | 默认懒执行 | 立即执行一次 |
| 适合 | 明确知道要监听谁 | 逻辑里有多个依赖，懒得列 |

```js
watchEffect(() => {
  // 用到了 keyword 和 page，两者变化都会触发
  console.log(keyword.value, page.value)
})
```

### 重要：异步请求的竞态问题

用户在搜索框里快速输入 `a` → `ab` → `abc`。
如果只写了 `watch(keyword, async (kw) => { list.value = await search(kw) })`，
可能出现 **`a` 的响应比 `abc` 晚回来，把正确结果覆盖掉的 bug**。

两种解法：

```js
// 方案 A：token 标记，丢弃过期结果
let token = 0
watch(keyword, async (kw) => {
  const my = ++token
  const data = await search(kw)
  if (my !== token) return        // 已经过期
  list.value = data
})

// 方案 B：AbortController 取消上一次请求
let controller
watch(keyword, async (kw) => {
  controller?.abort()
  controller = new AbortController()
  try {
    const res = await fetch(`/api?q=${kw}`, { signal: controller.signal })
    list.value = await res.json()
  } catch (e) {
    if (e.name !== 'AbortError') throw e
  }
})
```

### `watch` 的清理函数

同一个 watch 触发多次时，可以拿到 `onCleanup` 来清理上一次的副作用：

```js
watch(id, async (newId, oldId, onCleanup) => {
  const controller = new AbortController()
  onCleanup(() => controller.abort())   // 下次触发前会先执行
  const res = await fetch(`/api/${newId}`, { signal: controller.signal })
  data.value = await res.json()
})
```

## 4. 响应式是怎么实现的？（原理）

```
① 用 Proxy 包裹对象，拦截 get / set
② 组件渲染时读取数据 → get 被拦截 → 记录「这个渲染函数依赖了该数据」(track)
③ 数据被修改 → set 被拦截 → 找到所有依赖它的地方，通知它们重新渲染 (trigger)
④ 重新渲染不是立即的：会被放进微任务队列（nextTick），同一轮多次修改只渲染一次
```

关键点：

- **Vue 3 用 Proxy**，所以能侦测属性新增/删除、数组下标赋值、`Map`/`Set` 变化。
- Vue 2 用 `Object.defineProperty`，做不到这些，所以才需要 `Vue.set`。
- **批量更新**：同一 tick 内改 100 次数据，页面只渲染 1 次。
  所以改完数据立刻读 DOM 拿到的是旧值，需要 `await nextTick()`。

```js
count.value = 1
console.log(el.textContent)   // 还是旧值
await nextTick()
console.log(el.textContent)   // 现在是新值
```

### `shallowRef` / `shallowReactive` / `readonly`

```js
shallowRef(bigObject)    // 只有「整体替换」才触发更新，适合大数据/第三方实例
shallowReactive(obj)     // 浅层代理
readonly(obj)            // 只读代理，写入会警告（防止下游乱改）
```

## 5. 常见坑

| 坑 | 说明 |
| --- | --- |
| 忘记 `.value` | `count++` 不生效，要 `count.value++` |
| `reactive` 整体替换 | `state = {...}` 会断开响应式，改用 `ref` 或改 `Object.assign(state, newObj)` |
| `reactive` 解构 | 见上文，用 `toRefs` |
| 在 `computed` 里改状态 | 反模式，会造成难追踪的循环更新 |
| `watch` 里改被侦听的值 | 可能死循环，注意加条件 |
| 改完数据立刻读 DOM | 需要 `await nextTick()` |
| 异步请求不处理竞态 | 见上文，用 token 或 AbortController |
