## 1. 为什么要拆组件？

一个 500 行的 `.vue` 文件会变得：难读、难改、难复用、难测试。
组件的本质是**把「界面 + 逻辑」打包成一个可复用的单元**。

拆分的判断标准（从实用出发）：

- 这段 UI **重复出现**了（列表项、卡片、按钮）→ 必须拆
- 这段 UI **有独立的状态和交互**（搜索栏、弹窗、上传器）→ 值得拆
- 这个文件**超过 300 行**了 → 该拆
- 只是「看起来像一块」但没有独立状态 → 可以不拆（别为了拆而拆）

## 2. props：父 → 子

```vue
<!-- 父组件 -->
<UserCard :user="u" :following="isFollowed" compact />
```

```js
// 子组件
const props = defineProps({
  user: { type: Object, required: true },
  following: { type: Boolean, default: false },
  compact: { type: Boolean, default: false },
})
```

### 声明要点

```js
defineProps(['a', 'b'])                       // 简写：只写名字
defineProps({ title: String })                // 类型简写
defineProps({                                 // 完整写法（推荐）
  title: { type: String, required: true },
  count: { type: Number, default: 0 },
  tags: { type: Array, default: () => [] },     // 复杂类型必须用工厂函数
  level: { type: String, validator: (v) => ['low','mid','high'].includes(v) },
})

// 也可以独立写默认值
withDefaults(defineProps({ count: Number }), { count: 0 })
```

**为什么对象/数组的默认值必须是工厂函数？** 因为对象是引用类型，
如果直接写 `default: []`，所有组件实例会共享同一个数组，互相污染。

### 单向数据流（必须理解）

**props 是只读的。子组件不能修改 props。**

```js
props.user.name = 'hacked'   // ❌ 控制台警告
```

**为什么？** 父组件可能同时把这份数据传给了 5 个子组件。
如果谁都能改，出了问题你根本不知道是谁改的。
**数据只有一个修改入口**，这是可维护性的基石。

子组件想改数据怎么办？→ 抛事件，让父组件去改。

需要「基于 props 派生本地状态」时：

```js
const props = defineProps({ initial: Number })
// 用 props 做初始值，之后本地独立维护
const localValue = ref(props.initial)
// 想跟随 props 变化，用 watch
watch(() => props.initial, (v) => (localValue.value = v))
```

### 其他 props 细节

```vue
<!-- 布尔 prop 传 true 可以简写 -->
<Modal visible />

<!-- 静态字符串 -->
<Card title="标题" />

<!-- 动态 -->
<Card :title="dynamicTitle" />

<!-- 传对象的所有字段 -->
<Card v-bind="cardProps" />

<!-- 透传原生属性：class/style/id 会落在子组件根元素上（属性继承） -->
<Card class="mt-4" id="c1" />
```

## 3. emit：子 → 父

```js
// 子组件
const emit = defineEmits(['change', 'submit'])
emit('change', payload)          // 第一个参数是事件名，后面是数据
```

```vue
<!-- 父组件 -->
<Child @change="handleChange" />                 <!-- 收到 payload 作为第一个参数 -->
<Child @submit="(data) => doSubmit(data, 'x')" /> <!-- 内联 -->
```

### `v-model` 就是一种约定好的 props + emit

```vue
<Child v-model="value" />
<!-- 等价于 -->
<Child :model-value="value" @update:model-value="value = $event" />
```

Vue 3.4+ 用 `defineModel()` 一行实现：

```js
// 子组件
const model = defineModel({ type: Number, default: 0 })
model.value = 5     // 自动 emit('update:modelValue', 5)
```

多个 v-model：

```vue
<Range v-model:min="min" v-model:max="max" />
```
```js
const min = defineModel('min')
const max = defineModel('max')
```

## 4. 插槽 slot：让组件能「接收内容」

props 让组件可**配置**，slot 让组件可**包裹**。

```vue
<!-- 子组件 BasePanel.vue -->
<div class="panel">
  <header><slot name="header">{{ title }}</slot></header>   <!-- 具名 + 兜底内容 -->
  <div class="body"><slot>默认内容</slot></div>              <!-- 默认插槽 -->
</div>
```

```vue
<!-- 父组件 -->
<BasePanel title="标题">
  <template #header>自定义头部</template>
  这里是被放进默认插槽的内容
</BasePanel>
```

### 作用域插槽：把子组件的数据「反向」交给父组件渲染

```vue
<!-- 子组件：通过 slot 的 props 暴露数据 -->
<slot name="list" :items="items" :count="items.length" />

<!-- 父组件：接收并自由渲染 -->
<template #list="{ items, count }">
  <li v-for="i in items">{{ i }}</li>
</template>
```

**为什么需要它？** 因为插槽内容的**编译作用域在父组件**，
默认访问不到子组件的内部数据。作用域插槽是唯一的反向通道。
表格、树、下拉选择、虚拟列表这类组件都靠它实现「逻辑在子组件、渲染由父组件决定」。

## 5. 六种通信方式怎么选

| 场景 | 方案 | 说明 |
| --- | --- | --- |
| 父 → 子 | `props` | 首选 |
| 子 → 父 | `emit` | 首选 |
| 双向 | `v-model` / `defineModel` | 表单项组件 |
| 跨多层（配置类） | `provide` / `inject` | 主题、i18n、表单上下文 |
| 父要命令式控制子 | `ref` + `defineExpose` | 聚焦、打开弹窗、重绘图表 |
| 任意组件 / 全局 | **Pinia** | 用户信息、购物车、权限 |
| 兄弟组件 | 提升到共同父组件，或用 Pinia | ❌ 别用 EventBus |

### `provide` / `inject`

```js
// 祖先
provide('theme', themeRef)        // 提供 ref，后代仍是响应式
provide('switchTheme', fn)        // 也可以提供方法

// 任意深度后代
const theme = inject('theme', defaultValue)
```

**注意**：`inject` 拿到的就是 provide 的原始值。
如果 provide 的是 ref，模板里作为顶层变量会自动解包，脚本里要写 `.value`。

### `defineExpose`

`<script setup>` 组件默认是「封闭」的，父组件通过 ref 拿不到任何内部东西。
需要暴露什么就明确列出来，这其实是很好的封装。

```js
defineExpose({ focus, clear, getValue })
```

```js
// 父组件
const childRef = ref(null)
onMounted(() => childRef.value.focus())
```

> 只在「命令式操作」时用它（聚焦、播放动画、调用第三方图表 resize）。
> 能用 props/emit 表达的就不要用 ref 调用子组件方法。

## 6. 生命周期

```
创建 ──► 挂载 ──► 更新 ──► 卸载
```

| 钩子 | 时机 | 典型用途 |
| --- | --- | --- |
| （`<script setup>` 函数体） | 数据已初始化，DOM 未生成 | 初始化响应式数据 |
| `onBeforeMount` | 挂载前 | 极少用 |
| **`onMounted`** | DOM 已就绪 | **发请求、拿 DOM、初始化第三方库、注册事件** |
| `onBeforeUpdate` | 数据变化，DOM 未更新 | 极少用 |
| `onUpdated` | DOM 已更新 | ⚠️ 慎用（改状态会造成循环） |
| **`onBeforeUnmount`** | 卸载前 | **清理副作用** |
| `onUnmounted` | 卸载后 | 清理 |
| `onActivated` / `onDeactivated` | `keep-alive` 切换 | 刷新数据 / 暂停定时器 |
| `onErrorCaptured` | 捕获后代错误 | 错误边界 |

**父子顺序**：父 beforeMount → 子 mounted → 父 mounted。
所以**父组件 onMounted 里可以拿到子组件 ref**。

### 清理副作用（必背）

```js
let timer
onMounted(() => {
  timer = setInterval(tick, 1000)
  window.addEventListener('resize', onResize)
})
onBeforeUnmount(() => {
  clearInterval(timer)
  window.removeEventListener('resize', onResize)
})
```

**规则**：`onMounted`（或 setup）里注册了什么，`onBeforeUnmount` 里就清理什么。
典型对象：定时器、全局事件、WebSocket、IntersectionObserver、第三方实例。

### 模板引用（template ref）

```vue
<script setup>
const inputEl = ref(null)
onMounted(() => inputEl.value.focus())   // 必须在挂载后
</script>
<template>
  <input ref="inputEl" />
</template>
```

变量名必须和 `ref="xxx"` 字符串一致。
写在 `v-for` 里时，ref 会自动变成**数组**（对应每个实例）。

## 7. 常见坑

| 坑 | 解决 |
| --- | --- |
| 直接改 props | 用 emit 让父组件改 |
| 对象 prop 默认值写成 `default: {}` | 改成工厂函数 `default: () => ({})` |
| `defineEmits` 没声明就 emit | 声明后才有校验和提示 |
| 在 `onUpdated` 里改响应式数据 | 无限循环，改用 `computed` 或 `watch` |
| 忘记清理定时器 | 内存泄漏 + 报错 |
| 用 index 做 key 导致组件复用错乱 | 用唯一 id |
| 插槽里访问子组件数据 | 用作用域插槽 |
