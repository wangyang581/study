# 09 · 工程化与最佳实践

> 学完 17 课后，这一篇帮你把「能写出来」变成「写得能维护」。

## 1. 目录结构

```
src/
├── main.js
├── App.vue
├── api/                 # 接口层：按业务域分文件
│   ├── http.js          # axios 实例 + 拦截器
│   ├── user.js
│   └── order.js
├── assets/              # 静态资源（会被构建处理）
├── components/
│   ├── base/            # 通用无业务组件：BaseButton、BaseModal、BaseTable
│   └── business/        # 业务组件：UserCard、OrderList
├── composables/         # 可复用逻辑 useXxx
├── layouts/             # 布局组件：DefaultLayout、AdminLayout、BlankLayout
├── router/
│   ├── index.js
│   └── routes.js
├── stores/              # Pinia
├── styles/              # 全局样式、变量、reset
├── utils/               # 纯函数工具
├── views/               # 页面级组件（与路由一一对应）
└── types/               # TypeScript 类型（若用 TS）
```

**原则**：

- `views` 只做「组装」，复杂逻辑抽到 `composables`
- `components/base` 里不允许出现业务名词（这样才可复用）
- 一个文件只做一件事，**超过 300 行就考虑拆分**

## 2. 命名规范

| 类型 | 规范 | 例子 |
| --- | --- | --- |
| 组件文件 | PascalCase，多单词 | `UserCard.vue`、`TodoItem.vue` |
| 组件名（defineOptions） | PascalCase 多单词 | `name: 'UserCard'` |
| props | camelCase（模板用 kebab-case） | `defineProps({ userName })` → `:user-name="x"` |
| 事件 | kebab-case，动词过去式/名词 | `@update`, `@item-selected`, `@change` |
| composable | use + PascalCase | `useMouse`, `useRequest` |
| store | use + PascalCase + Store | `useUserStore` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 布尔 | is/has/can/should 开头 | `isLoading`, `hasError`, `canSubmit` |

**避免**：`data`、`list`、`info`、`temp`、`handleClick1` 这类无信息量的名字。

## 3. 组件设计原则

### ① 单一职责

一个组件只解决一个问题。`UserCardWithFollowButtonAndEditModal.vue` 就是信号。

### ② props 是 API，要设计好

```js
// ❌ 布尔开关堆叠，组合爆炸
defineProps({ isPrimary: Boolean, isDanger: Boolean, isSmall: Boolean })

// ✅ 用枚举语义
defineProps({ variant: String /* 'primary' | 'danger' */, size: String /* 'sm' | 'md' */ })
```

### ③ 向上暴露事件，而不是暴露内部状态

```vue
<!-- ✅ 子组件说"用户点了删除"，父组件决定怎么做 -->
<button @click="emit('delete', item.id)">

<!-- ❌ 子组件直接调 API 删数据，父组件不知道发生了什么 -->
```

### ④ 状态尽量靠近使用它的地方

```
局部（组件内 ref）
  → 提升到父组件（props/emit）
    → 跨层级（provide/inject）
      → 全局（Pinia）
        → 服务端状态（请求层 / vue-query）
```

**能用左边的就不要用右边的。**

### ⑤ 受控 vs 非受控

表单组件优先「受控」（`v-model` 由父组件持有状态），
内部状态只在必要时使用（比如输入框的临时草稿）。

## 4. 性能优化

### 4.1 减少不必要的渲染

```js
// 用 computed 缓存派生数据，而不是在模板里算
const filtered = computed(() => list.value.filter(...))
```

```vue
<!-- v-memo：依赖不变时跳过整个子树的更新（Vue 3.2+） -->
<div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
```

```vue
<!-- v-once：内容永不变时只渲染一次 -->
<Footer v-once />
```

```js
// 稳定 props：避免每次渲染都创建新对象/函数
// ❌ 每次都创建新的对象 → 子组件 props 永远"变了"
<Child :style="{ color: 'red' }" :on-change="() => doX()" />
// ✅ 提前定义
const style = { color: 'red' }
function onChange() { doX() }
```

### 4.2 大列表

- 用**虚拟滚动**（`vue-virtual-scroller`、`@vueuse/core` 的 `useVirtualList`）
- 分页加载（每页 20~50 条）
- 避免在每一项里做重计算（提到父组件用 `computed` 算好）

### 4.3 懒加载

```js
const Heavy = defineAsyncComponent(() => import('./Heavy.vue'))
// 配合 Suspense 显示 loading
```

```js
// 路由懒加载（本项目已用）
{ path: '/x', component: () => import('@/views/X.vue') }
```

### 4.4 保持组件轻量

```js
// shallowRef 处理大对象/第三方实例：只关心整体替换
const chart = shallowRef(null)
const bigData = shallowRef(rawData)

// markRaw：明确告诉 Vue「这个对象不需要响应式」
const instance = markRaw(new ThirdPartyLibrary())
```

### 4.5 图片与资源

- 用 WebP/AVIF、懒加载 `loading="lazy"`、显式宽高防抖动
- 小图标用 SVG 或 icon font，别用大图
- 构建产物分析：`npx vite-bundle-visualizer`

### 4.6 打包体积

```bash
npm run build          # 看产物大小
npx vite-bundle-visualizer
```

- 按需引入组件库（Element Plus / Ant Design Vue 都支持）
- 用 `unplugin-vue-components` 自动按需注册
- 检查是否误引入了整个 lodash / moment（改 `lodash-es` / `dayjs`）

## 5. 可维护性实践

### 5.1 统一错误处理

```js
app.config.errorHandler = (err, instance, info) => {
  console.error('[全局错误]', err, info)
  // 上报到 Sentry / 自建监控
}

window.addEventListener('unhandledrejection', (e) => { /* 未捕获的 Promise */ })
```

### 5.2 环境变量

```bash
# .env.development
VITE_API_BASE_URL=/api
# .env.production
VITE_API_BASE_URL=https://api.example.com
```

```js
const base = import.meta.env.VITE_API_BASE_URL
// 只有 VITE_ 前缀的变量会被暴露给客户端
```

### 5.3 日志与埋点

集中到 utils，别散落各处；生产环境可通过构建开关关闭 `console`。

## 6. 调试技巧

| 工具 | 用途 |
| --- | --- |
| **Vue DevTools** | 组件树、props/state、Pinia、路由、性能 |
| `console.log` + 断点 | 最直接 |
| `debugger` 语句 | 在源码位置断住 |
| Vue DevTools 的 "Timeline" | 追踪状态变化来源 |
| `app.config.performance = true` | 组件渲染性能打点 |
| Network 面板 | 接口耗时、竞态 |

**调试响应式没生效的思路**：

1. 打印出来确认数据真的变了（`console.log(list.value)`）
2. 检查是否解构丢了响应式（`props` / `reactive` / `store`）
3. 检查是否用了 `shallowRef` 或 `markRaw`
4. 检查是否在 `nextTick` 之前读的 DOM

## 7. 高频坑清单（收藏级）

| 类别 | 坑 | 正确做法 |
| --- | --- | --- |
| 响应式 | 忘记 `.value` | `count.value++` |
| 响应式 | 解构 `props`/`reactive`/`store` 丢响应式 | `toRef` / `toRefs` / `storeToRefs` |
| 响应式 | 改完数据立刻读 DOM | `await nextTick()` |
| 响应式 | `onUpdated` 里改状态 | 会无限循环 |
| 列表 | `:key` 用 index | 用唯一 id |
| 列表 | 同时用 `v-if` 和 `v-for` | 先 `computed` 过滤 |
| 事件 | `@click="fn()"` 立即执行 | `@click="fn"` |
| 表单 | 提交后整页刷新 | `@submit.prevent` |
| 表单 | `v-model` 数字拿到字符串 | `.number` 或手动转换 |
| 组件 | 直接改 props | emit 事件 |
| 组件 | 对象 props 默认值写 `{}` | 工厂函数 `() => ({})` |
| 生命周期 | 忘记清理定时器/监听 | `onBeforeUnmount` |
| 路由 | history 模式刷新 404 | 服务端 fallback 到 index.html |
| 路由 | 组件复用不重新请求 | `watch route.params` |
| 路由 | query 参数是字符串 | 手动 `Number()` |
| store | `const { x } = store` | `storeToRefs(store)` |
| 异步 | 竞态覆盖 | token 或 `AbortController` |
| 异步 | `fetch` 4xx 不报错 | 手动 `if (!res.ok)` |
| 样式 | `scoped` 改不了子组件 | `:deep()`（但优先用 props/CSS 变量） |
| 安全 | `v-html` 渲染用户输入 | DOMPurify 消毒 |


### 一个最小的组件测试

```js
import { mount } from '@vue/test-utils'
import { describe, expect, it } from 'vitest'
import Counter from '@/components/Counter.vue'

describe('Counter', () => {
  it('点击后计数 +1', async () => {
    const wrapper = mount(Counter, { props: { initial: 0 } })
    await wrapper.find('button').trigger('click')
    expect(wrapper.text()).toContain('1')
  })
})
```
