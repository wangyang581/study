# 07 · 异步数据与网络请求

> 对应课程：[13 异步数据与网络请求](../src/views/Lesson13Async.vue)

## 1. 先建立「四态」思维

任何一个异步界面都有 **4 种状态**，一个都不能漏：

| 状态 | 用户看到什么 |
| --- | --- |
| **加载中** | 骨架屏 / loading 动画（不要只写一行"加载中"） |
| **成功** | 数据渲染 |
| **空数据** | 「暂无内容」+ 引导操作（最容易被忘记！） |
| **失败** | 错误原因 + **重试按钮** |

用**一个** `status` 字段管理，比用 `isLoading` / `isError` / `isSuccess` 三个布尔量清晰得多
（3 个布尔有 8 种组合，其中 6 种是非法的）。

```js
const status = ref('idle')   // idle | loading | success | error
const data = ref(null)
const error = ref('')

async function load() {
  status.value = 'loading'
  error.value = ''
  try {
    data.value = await api()
    status.value = 'success'
  } catch (e) {
    error.value = e.message
    status.value = 'error'
  }
}
```

```vue
<div v-if="status === 'loading'">骨架屏</div>
<div v-else-if="status === 'error'">错误 + 重试</div>
<ul v-else-if="data.length">列表</ul>
<p v-else>空状态</p>
```

## 2. 在什么时机发请求？

```js
// ① 组件挂载时（最常见）
onMounted(() => load())

// ② 路由参数变化时（组件被复用，不会重新挂载！）
watch(() => route.params.id, () => load(), { immediate: true })

// ③ 用户操作时
function onSubmit() { load() }
```

> ⚠️ 经典 bug：`/user/1` → `/user/2` 时组件**不会重新创建**，`onMounted` 不会再执行。
> 所以要 `watch` 参数，或用 `:key="route.fullPath"` 强制重建组件。

## 3. `fetch` 的坑

```js
const res = await fetch('/api/users')
// ❌ fetch 对 404 / 500 不会 reject！必须手动判断
if (!res.ok) throw new Error(`HTTP ${res.status}`)
const data = await res.json()   // 也要 await（读流也是异步的）
```

其他注意点：

- `fetch` 默认不带 cookie（跨域时需要 `credentials: 'include'`）
- 没有超时机制，需要配合 `AbortController` + `setTimeout`
- 请求体是 JSON 时必须手动设 header + stringify：

```js
fetch('/api', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload),
})
```

## 4. 并发、串行与竞态

```js
// ❌ 串行：总耗时 500 + 800 = 1300ms
const a = await apiA()
const b = await apiB()

// ✅ 并发：总耗时 ≈ 800ms
const [a, b] = await Promise.all([apiA(), apiB()])

// 有依赖时必须串行
const user = await getUser(id)
const orders = await getOrders(user.id)

// 谁成功用谁（失败也返回结果）
const results = await Promise.allSettled([apiA(), apiB()])
// 谁先回来用谁（常用于超时兜底）
const fastest = await Promise.race([apiA(), timeout(3000)])
// 顺序执行（有依赖的数组）
for (const id of ids) { await del(id) }
```

### 竞态（race condition）

搜索框快速输入时，先发出的请求可能后返回，覆盖掉正确结果。见
[03 文档的「竞态」小节](03-响应式-计算属性-侦听器.md) —— token 标记或 `AbortController`。

## 5. 封装一个可复用的请求层

真实项目不会在每个组件里裸写 `fetch`。推荐三层结构：

```
组件  →  composable (useRequest)  →  request 工具 (axios 实例)  →  后端 API
```

### 第一层：`request` 工具（统一处理公共逻辑）

```js
import axios from 'axios'

export const http = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL ?? '/api',
  timeout: 10000,
})

// 请求拦截器：统一加 token
http.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// 响应拦截器：统一解包 + 统一错误提示 + 401 跳登录
http.interceptors.response.use(
  (res) => res.data,
  (err) => {
    const msg = err.response?.data?.message ?? err.message ?? '网络错误'
    if (err.response?.status === 401) {
      // 不要 import router 造成循环依赖，用 location 或事件总线
      window.location.href = '/login'
    }
    return Promise.reject(new Error(msg))
  },
)
```

### 第二层：API 模块（按业务组织）

```js
// src/api/user.js
import { http } from './http'

export const userApi = {
  list: (params) => http.get('/users', { params }),
  detail: (id) => http.get(`/users/${id}`),
  create: (data) => http.post('/users', data),
  update: (id, data) => http.put(`/users/${id}`, data),
  remove: (id) => http.delete(`/users/${id}`),
}
```

### 第三层：composable（把「状态」也复用）

```js
export function useRequest(fetcher, { immediate = true, immediateArgs = [] } = {}) {
  const data = ref(null)
  const status = ref('idle')
  const error = ref(null)

  async function run(...args) {
    status.value = 'loading'
    error.value = null
    try {
      data.value = await fetcher(...args)
      status.value = 'success'
      return data.value
    } catch (e) {
      error.value = e
      status.value = 'error'
      throw e
    }
  }

  if (immediate) run(...immediateArgs)
  return { data, status, error, run }
}
```

组件里就变得非常干净：

```vue
<script setup>
import { useRequest } from '@/composables/useRequest'
import { userApi } from '@/api/user'

const { data: users, status, error, run } = useRequest(() => userApi.list())
</script>

<template>
  <div v-if="status === 'loading'">加载中…</div>
  <div v-else-if="status === 'error'">{{ error.message }} <button @click="run()">重试</button></div>
  <ul v-else><li v-for="u in users" :key="u.id">{{ u.name }}</li></ul>
</template>
```

> 也可以直接用成熟方案：**@tanstack/vue-query**（自动缓存、重试、失效、分页）、
> **SWRV**（stale-while-revalidate）。生产项目很值得上。

## 6. 加载体验优化清单

| 技巧 | 说明 |
| --- | --- |
| 骨架屏 | 比 spinner 更少「跳动感」，用户感知更快 |
| 乐观更新 | 先改 UI，再发请求，失败回滚（点赞、收藏） |
| 预加载 | 鼠标 hover 菜单时提前请求目标页面数据 |
| 缓存 | 相同参数短时间内的请求直接返回上次结果 |
| 防抖 / 节流 | 搜索输入用防抖（300~500ms），滚动用节流 |
| 分页 / 虚拟列表 | 大列表只渲染可视区域（vue-virtual-scroller） |
| 请求去重 | 同一资源的并发请求合并成一个 |
| 超时与重试 | 失败自动重试 1~2 次（指数退避），超时给用户提示 |

## 7. 安全与工程注意

- **敏感信息不要放在前端**：密钥、数据库连接串
- 前端校验只为体验，**后端必须再校验一次**
- `v-html` 渲染用户内容有 **XSS 风险**，需要消毒（DOMPurify）
- 用 HTTPS；token 优先放 **HttpOnly Cookie**（而不是 localStorage，后者易被 XSS 窃取）
- 跨域问题由**后端 CORS** 或**开发代理**解决：

```js
// vite.config.js
server: {
  proxy: {
    '/api': { target: 'http://localhost:3000', changeOrigin: true },
  },
}
```
